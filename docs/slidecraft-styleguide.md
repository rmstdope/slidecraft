# Slidecraft style guide

The look of Slidecraft's own interface: the home page, settings, the deck workspace, the gallery,
the dialogs and the presenter window. Slides follow their deck's theme instead; this guide is for
the tool around them. The decisions behind it are in
[`plans/ui-redesign-plan.md`](plans/ui-redesign-plan.md).

## Brand

Slidecraft is about structure: a deck is built from parts that fit together. The voice is quiet
and precise, never shouting. Tagline: *structure for your stories*.

## Logo

Two L-shaped brackets at opposite corners, yellow top left and teal bottom right, framing a dot:
the slide frame around the idea at its centre.

- In the app it is the `Logo` component (`src/ui/logo.tsx`): the brackets keep brand yellow and
  the agent teal, the dot follows the text colour, so it works in both themes.
- Static files: `public/logo-on-dark.svg`, `public/logo-on-light.svg`.
- Clear space around the mark equals the dot's diameter.
- Never smaller than 16 px; never stretched, rotated or recoloured.
- Favicons: `public/favicon.svg` plus PNGs at 16, 32, 48, 64, 128, 180 (Apple touch), 192 and 512 px,
  generated by `node scripts/generate-favicons.mjs`.

## Themes

The interface has a **light** and a **dark** theme, and **System** (the default) follows the
operating system. People choose on *Settings › Appearance* or with the switch in the home
sidebar; the choice is kept in the browser. The full-screen player and the presenter window are
always dark, and slides always keep their deck's own theme.

## Colour roles

Components name a role, never a colour. Each role is a CSS custom property `--sc-<role>` in
`src/styles/app.css` and a Tailwind colour (`tw:bg-panel`, `tw:text-muted`, `tw:shadow-hairline`).

| Role | Light | Dark | Use |
|---|---|---|---|
| `ground` | `#ededea` | `#09090b` | window background |
| `panel` | `#ffffff` | `#121214` | sidebar cards, the main card, the agent panel |
| `panel-alt` | `#f7f7f5` | `#17171a` | slide rail, card headers |
| `raised` | `#ffffff` | `#1c1c1f` | composer, popovers, menus, dialogs |
| `field` | `#f0f0ee` | `#1f1f23` | inputs, chips, message bubbles, quiet buttons |
| `line` | `#e4e4e7` | `#26262b` | 1 px borders and hairlines |
| `fg` / `fg-2` / `muted` | `#0a0a0a` / `#3f3f46` / `#6b6b70` | `#f4f4f5` / `#d4d4d8` / `#a1a1aa` | text, secondary text, captions |
| `primary` / `on-primary` | `#0a0a0a` / `#ffffff` | `#f4f4f5` / `#0a0a0a` | the primary button; it inverts with the theme |
| `accent` | `#f5b400` | the person's choice, violet `#9b8afb` by default | highlights |
| `accent-tint` / `on-accent-tint` | `#fef7e0` / `#7a5600` | accent at 16 % / accent | context chips, notices |
| `focus` | `#a87b00` | accent | focus rings and selection outlines |
| `agent` | `#0a7363` | `#2bb39c` | the agent, success, live status |
| `added` / `removed` | `#0a7363` / `#b42318` | `#5fd3bf` / `#f87171` | diffs, errors, danger |
| `canvas` / `canvas-dot` | `#e4e4e0` / `#d2d2cd` | `#0e0e10` / `#232327` | the dotted canvas behind a slide preview |
| `brand` | `#f5b400` | `#f5b400` | the logo only |

Text roles meet 4.5:1 on every surface they sit on, and outlines 3:1. Brand yellow is too light
for an outline on white, which is why `focus` exists.

## Typography

| Use | Face | Size |
|---|---|---|
| Page headings, the wordmark | Zilla Slab 600 (`tw:font-display`) | 40–48 px, dialogs 22–28 px |
| Interface text | Source Sans 3 (`tw:font-sans`) | 14 px; 13 px in toolbars; 12 px captions |
| Section labels | Source Sans 3, semibold, upper case, tracked | 11–13 px, muted |
| Numbers, paths, code, keys | Geist Mono (`tw:font-mono`) | 12–13 px; the code editor 14 px |

## Shape, depth and motion

- **Radii:** 8–10 px for controls, 12–16 px for cards, panels and dialogs.
- **Depth:** surfaces get lighter as they rise in dark mode (ground, panel, raised); a 1 px
  hairline (`tw:shadow-hairline`) separates them, with a soft shadow (`--sc-elev`) only on what
  floats (main card, composer, menus, dialogs).
- **Motion:** 150 ms for hover and focus, 300 ms for panels and theme changes; nothing bounces.

## Components

The chrome is built from `src/ui/` (Radix primitives styled with Tailwind; see
[`plans/ui-redesign-plan.md`](plans/ui-redesign-plan.md) §3): `Button` (primary, secondary,
ghost, quiet, danger), `Input`, `Textarea`, `Field`, `Select`, `NativeSelect`,
`SegmentedControl`, `Switch`, `Badge`, `Card`, `StatusDot`, `Kbd`, `Tooltip`, `Dialog`, `Menu`,
`Popover`, `Sheet`, `LoadingScreen` and `Logo`. A page puts `sc-app` on its root; every utility
carries the `tw:` prefix.

## Do and don't

| Do | Don't |
|---|---|
| use the roles and `src/ui` components | write colours or old `tool.css`-style classes |
| keep the primary button for the one main action | put two primary buttons side by side |
| use `focus` for rings and selection | outline with brand yellow on a light surface |
| use hairlines and quiet fills | use heavy drop shadows or gradient washes |
| keep status in text as well as colour | rely on colour alone |
| check both themes | assume the interface is dark |
